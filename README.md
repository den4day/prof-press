# Тестовое задание — страница «О компании» (ООО «Рыжий Кот»)

Адаптивная страница по макету Figma с всплывающей формой обратной связи,
клиентской и серверной валидацией и AJAX-отправкой на PHP.

## Как запустить

Нужен PHP 8 или новее (`php -v`).

```bash
git clone git@github.com:den4day/prof-press.git
cd prof-press
php -S localhost:8080
```

Открыть в браузере: <http://localhost:8080>

> Открывать `index.html` двойным кликом (через `file:///`) нельзя — форма
> отправляет запрос в `index.php`, и без PHP-сервера он не выполнится.

## Структура проекта

```
├── index.html   — разметка страницы, popup с формой
├── style.css    — все стили, включая адаптив
├── main.js      — меню, popup, валидация, отправка формы (Fetch API)
├── index.php    — приём и проверка данных формы, JSON-ответ
├── images/      — логотип, иконки, фото склада, декоративная «лапа»
└── README.md
```

## Технологии

- HTML5, CSS3 (Flexbox, Grid, custom properties, media queries)
- Нативный JavaScript (ES5-совместимый синтаксис, без сборки)
- PHP 8 (встроенный сервер `php -S`)
- Шрифт Manrope подключён с Google Fonts (в макете он же)

Никаких фреймворков и библиотек не используется.

## Что реализовано

**Вёрстка по макету**

- Desktop-версия (макет 1740px): полная шапка с верхней полосой, логотипом,
  кнопкой «Каталог», поиском с выбором области, блоком «Регистрация / Вход»
  и навигацией по категориям.
- Tablet и Mobile (макеты 960 / 640 / 460px): шапка с бургером, логотипом,
  иконкой входа и поиском на отдельной строке. Контент в одну колонку,
  блок «Компания в цифрах» перестраивается в 4 / 2×2 колонки, футер — в 4 / 3 / 2
  колонки. Дополнительно проверено на ширине 360px.
- Точки перелома: `1399px`, `1023px`, `767px`, `479px`.
- Декоративная «лапа» вынесена в SVG и накладывается с прозрачностью, как в макете.
- Мобильное меню (в макете его нет): выезжающая панель с категориями и ссылками,
  закрывается крестиком, кликом по фону и клавишей Esc.

**Popup с формой**

- Открывается кнопкой «Форма обратной связи», закрывается крестиком, кликом
  вне окна и клавишей Esc. Пока окно открыто, прокрутка страницы заблокирована.
- Фокус при открытии ставится в первое поле, при закрытии возвращается на кнопку.
- Поля: имя, e-mail; кнопка «Отправить»; текст согласия на обработку данных.

**Проверка на JavaScript** (`main.js`)

- Имя: не пустое, минимум 2 символа (пробелы по краям обрезаются).
- E-mail: не пустой, соответствует формату `имя@домен.зона`.
- Ошибка показывается под конкретным полем, поле подсвечивается красным.
  Проверка срабатывает при уходе с поля и при отправке; ошибка исчезает,
  как только пользователь исправил значение.
- При наличии ошибок запрос на сервер не отправляется.

**AJAX-отправка**

- `fetch('index.php', { method: 'POST' })`, данные передаются в формате JSON.
- Страница не перезагружается. На время запроса кнопка блокируется
  («Отправка…»), чтобы исключить двойную отправку.
- Ответ сервера разбирается всегда — и при `200`, и при `422`, поэтому ошибки
  серверной проверки тоже показываются под полями.
- При обрыве сети или ответе не в формате JSON показывается понятное сообщение.
- После успеха форма заменяется сообщением сервера «Спасибо, заявка принята».
  При следующем открытии popup форма снова пустая.

**Обработка на PHP** (`index.php`)

- `GET /` — отдаёт `index.html`, поэтому `php -S localhost:8080` сразу открывает страницу.
- `POST /index.php` — принимает JSON **или** `application/x-www-form-urlencoded`,
  повторно проверяет данные теми же правилами (`mb_strlen`, `filter_var … FILTER_VALIDATE_EMAIL`)
  и отвечает JSON:
  - `200` `{ "success": true, "message": "Спасибо, заявка принята" }`
  - `422` `{ "success": false, "message": "…", "errors": { "name": "…", "email": "…" } }`
  - `400` при некорректном JSON.
- Реальная отправка письма по условию не делается; место для неё отмечено в коде.

## Принятые решения

- **Серверная проверка дублирует клиентскую**, потому что JavaScript выполняется
  в браузере пользователя: его можно отключить или отправить запрос напрямую.
- **JSON вместо form-urlencoded** — проще расширять (вложенные данные), но PHP
  на всякий случай принимает оба формата.
- **HTTP-коды 422 / 400** для ошибок вместо `200` с флагом — так ответы понятны
  и без чтения тела, а JS всё равно разбирает JSON при любом статусе.
- **Текст ошибки под полем позиционируется абсолютно**, чтобы форма не «прыгала»
  при появлении и исчезновении сообщений.
- **Сетка «Компания в цифрах» заполняется по колонкам** (`grid-auto-flow: column`)
  на десктопе: так один и тот же порядок элементов в HTML даёт нужный порядок
  и в макете 1740 (2×2), и в 960 (в строку), и в 640/460 (2×2 в другом порядке).
- **Доступность**: семантические теги, `aria-*` на popup и меню, `label` для
  полей (скрыты визуально), управление с клавиатуры, видимый `:focus-visible`.
- В макете есть опечатки («О компаниии», «Настольный игры») — в вёрстке они исправлены.

## Проверка

- Страница открывается без ошибок в консоли.
- Адаптив проверен на ширинах 1740, 1470, 960, 640, 460, 360px.
- Popup открывается и закрывается всеми тремя способами.
- Валидация: пустые поля, имя из 1 символа, e-mail без домена — отклоняются.
- `index.php` проверен отдельно через `curl` (валидные данные, невалидные,
  form-urlencoded, битый JSON).
